# Specification Source Rules

## 단일 원본

[Google Sheet `명세`](https://docs.google.com/spreadsheets/d/1Ax9AWH10wm7VHtBsduI6X_CZqnCXEYDmUdFruOcUGfo/edit?gid=0#gid=0)가 요구사항, 기능, API와 데이터 명세의 단일 원본입니다.

- Spreadsheet ID: `1Ax9AWH10wm7VHtBsduI6X_CZqnCXEYDmUdFruOcUGfo`
- 기능명세: `02_기능` 탭 (`sheetId: 102`)
- 요구사항: `01_요구사항` 탭 (`sheetId: 101`)
- API 명세: `03_API` 탭 (`sheetId: 103`)
- 요구사항·기능·API 연결 검증: `00_추적성` 탭 (`sheetId: 0`)
- 데이터 명세: `04_엔터티`, `05_컬럼`, `06_관계`, `08_코드값` 탭
- 미결정·검토 항목: `07_이슈` 탭
- 원본 출처: `99_원본` 탭

Git에 기능명세 CSV나 별도의 명세 사본을 만들지 않습니다.

## 구현 전 확인

1. 구현 대상의 `기능_ID`를 `02_기능`에서 확인합니다.
2. 연결된 `요구사항_ID`를 `01_요구사항`에서 확인합니다.
3. API 작업이면 연결된 `API_ID`를 `03_API`에서 확인합니다.
4. `00_추적성`의 연결 상태가 정상인지 확인합니다.
5. 각 행의 `결정상태`를 확인합니다. `PROPOSED`는 승인된 계약으로 임의 해석하지 않습니다.
6. 데이터 작업이면 엔터티·컬럼·관계·코드값 탭을 함께 확인합니다.

## 결정상태

- `PROPOSED`: 제안 또는 검토 중인 명세이며 구현 계약으로 사용하지 않습니다.
- `APPROVED`: 구현 가능한 승인 명세입니다.
- `SUPERSEDED`: 효력을 잃은 명세이며 신규 구현과 변경의 근거로 사용하지 않습니다.
- 상태가 비어 있거나 정의되지 않은 값이면 구현하지 않고 확인을 요청합니다.
- 사용자가 현재 작업에서 `PROPOSED` 항목 구현을 명시적으로 승인하면 작업은 진행할 수 있지만, Sheet 상태 변경 권한은 별도로 확인합니다.

## 코드 변경 규칙

- 구현, 테스트와 리뷰 설명에서 관련 `기능_ID`와 `API_ID`를 추적할 수 있게 합니다.
- 명세와 코드가 충돌하면 코드를 임의로 맞추지 않고 충돌 내용을 먼저 알립니다.
- 명세에 없는 필드, 상태, 오류 코드와 업무 규칙을 추정해 추가하지 않습니다.
- Google Sheet는 사용자가 명시적으로 요청하지 않는 한 읽기 전용으로 취급합니다.
- Sheet의 표시명보다 영구 ID를 추적 기준으로 사용합니다.
