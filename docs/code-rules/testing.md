# Testing Rules

## Given-When-Then

- 단위 테스트는 준비(`Given`)·실행(`When`)·검증(`Then`)의 세 단계를 구분합니다.
- 구분은 주석 또는 빈 줄로 표현하며 의미 없는 주석을 기계적으로 반복하지 않습니다.
- 테스트 하나는 하나의 행위 또는 업무 규칙을 검증합니다.

- 구현 세부사항보다 외부에서 관찰 가능한 동작과 업무 규칙을 검증합니다.
- 정상 흐름뿐 아니라 경계값, 실패, 권한 거부와 중복 요청을 고려합니다.
- 버그 수정에는 가능하면 수정 전 실패하고 수정 후 통과하는 회귀 테스트를 추가합니다.
- 테스트는 실행 순서, 현재 시간, 네트워크와 다른 테스트의 데이터에 불필요하게 의존하지 않습니다.
- 테스트 이름은 조건, 행위와 기대 결과를 알 수 있게 작성합니다. `@DisplayName`을 사용하면 업무 언어로 명확히 표현합니다.
- Mock은 외부 경계를 격리하는 데 사용하고 구현 내부 호출 순서를 과도하게 고정하지 않습니다.
- 데이터베이스, 직렬화와 외부 Adapter 계약은 필요한 수준의 통합 테스트로 확인합니다.
- 단순 커버리지 수치보다 중요한 분기와 실패 가능성이 높은 경로를 우선합니다.
- 테스트를 비활성화해 검사를 통과시키지 않습니다.
- 예외 테스트는 가능한 경우 예외 타입뿐 아니라 `ErrorCode`도 검증합니다.
- 시간, UUID와 외부 호출은 테스트에서 제어할 수 있는 의존성으로 분리합니다.
