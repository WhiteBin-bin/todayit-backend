# Database Code Rules

- 스키마 변경은 재현 가능한 Migration으로 관리하며 운영 DB를 수동 변경하는 절차에 의존하지 않습니다.
- 테이블과 컬럼 이름은 하나의 명명 규칙을 사용하고 약어를 일관되게 관리합니다.
- N:M 관계는 명시적인 관계 테이블로 표현합니다.
- 참조 무결성과 삭제 동작은 애플리케이션 코드에만 맡기지 않고 명시적으로 결정합니다.
- 인덱스는 실제 조회 조건과 정렬을 근거로 추가합니다.
- 시간 값의 시간대, 정밀도와 생성·수정 주체를 명확히 합니다.
- Soft Delete는 복구·감사·참조 요구가 있을 때만 사용하며 모든 조회에 미치는 영향을 테스트합니다.
- 데이터 손실 가능성이 있는 Migration에는 사전 검증, 백업과 복구 계획이 필요합니다.
- ORM Entity를 API 응답이나 업무 계약으로 직접 노출하지 않습니다.
- Aggregate 외부에서는 내부 Entity를 개별 저장하지 않고 Aggregate Root의 Repository를 통해 변경합니다.
- 관계 테이블이 독립 Aggregate인지 한 Aggregate의 내부 구현인지 먼저 결정한 뒤 Repository 소유권을 부여합니다.

DBMS, PK 방식, 관계·로그 접미사는 기술과 운영 요구가 정해지기 전에는 확정하지 않습니다.
